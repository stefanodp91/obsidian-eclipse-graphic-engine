# 0.2.1 cumulative patch

Release date: 2026-09-08, re-cut from the 2026-09-06 patch to absorb the documentation and
source-comment changes that had followed it. A release must carry a runtime change, so those
changes joined this patch instead of forming one of their own. The runtime is unchanged from the
2026-09-06 build — every code line is identical, and no export, signature or native contract moves —
but the artifacts were rebuilt from the new release commit, so their checksums differ from the ones
published on 2026-09-06. A consumer that pinned the earlier archive by integrity must refresh its
lockfile rather than expect the same bytes.

The full local aggregate release gate passes.
Official artifacts are produced by the `v0.2.1` tag workflow after its own validation.
After publication, repository history was sanitized on explicit request. Commit and tag
identifiers changed; the repository-only sensitive-data checker was corrected in the tagged
source. Runtime package and sample source trees are unchanged, as are the published archives
and their checksums. The original successful workflow identifies the pre-sanitization commit.
Tracked content must never embed personal author identities.

## Included corrections

- All documented facade mutators reject calls after disposal before reaching host services.
  Reads, subscriptions and previously returned cleanup callbacks retain their behavior.
- The optional render-loop gate establishes ownership on first reconciliation and at the end
  of the one-second startup window. Positive caps use cumulative deadlines; changes and resume
  reset pacing. Hosts still own startup integration, scene/engine disposal and rendering capacity.
- Baked cel outlines measure the owning component surface, bound corner/missed-ray strokes by
  volume/area, accept closed collapsed caps, and clear obsolete fallback passes.
  First-use bake work and emitted triangle counts can increase; validate content in prewarm.

## Absorbed documentation changes

- Source comments no longer carry internal roadmap identifiers. Seven comments — in the core
  application barrel, the Havok, memory and React adapters, the engine options and the iOS display
  plugin — named phases of a plan that a reader outside this project cannot resolve; one of them was
  also the last untranslated word left by the 0.2.0 comment pass. Each now states what it meant.
- The repository documents its sibling audio engine, which applies the same library/host boundary to
  sound. It is not a dependency of this repository, and this repository is not a dependency of it.

## Compatibility

No public export or signature is intentionally removed. Existing host cleanup must obey the
already documented disposal contract. The cel surface remains experimental: inspect thin/tapered
parts and outlines restored on previously skipped components before adopting the patch.
Dynamic PBR/per-mesh and shader fallbacks retain their explicit uniform width.

All six repository manifests use 0.2.1. Both distributed packages are versioned together; native
Android/iOS source contracts are unchanged. The optional Capacitor adapter requires core ^0.2.1.
The sample still uses Reactylon ownership, not the optional render-loop gate or cel outlines.

## Local validation

Clean `npm ci` on Node 22/npm 10 succeeds without changing external dependency resolutions.
Core 149/149 and sample 9/9 tests pass, as do typechecks, native contracts, documentation checks
and all package/sample builds. Declaration export names match 0.2.0 on all core subpaths
(root 62, Babylon 271, React 7, Reactylon 3, cache 1). The clean tarball consumer exercises all
seven runtime entry points with their documented peers, including the optional Firebase web SDK.
This validates bundler-based ESM consumption; it is not a direct Node.js runtime compatibility claim.
The full `npm run check` passed for the tagged revision. Subsequent author-policy corrections
are recorded in the unreleased changelog and do not change the already published artifacts.
Local candidate checksums are not official release checksums. Publication rebuilds from the
release commit and records its own assets and SHA-256 file.

## Adoption checks

Release consumers must use the eventual immutable official artifacts. Verify first activation,
phase caps by actual scene renders, pause/resume, resource disposal, pooled/direct outlines and
prewarm costs. Revisit workarounds that compensated for the old scheduler. Confirm native packaging
and visual acceptance on the host's target devices; a generic browser probe is not host certification.
