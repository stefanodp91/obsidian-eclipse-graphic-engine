# 0.2.2 documentation patch

Release date: 2026-09-08. Documentation and source comments only: every code line is unchanged
from 0.2.1, and no public export, signature or native contract moves. Official artifacts are
produced by the `v0.2.2` tag workflow after its own validation.

## Included changes

- Source comments no longer carry internal roadmap identifiers. Seven comments — in the core
  application barrel, the Havok, memory and React adapters, the engine options and the iOS display
  plugin — named phases of a plan that a reader outside this project cannot resolve; one of them was
  also the last untranslated word left by the 0.2.0 comment pass. Each now states what it meant: a
  placeholder says it is not implemented yet, and a note about behavior that is not routed through
  the facade says so instead of pointing at a schedule.
- The repository documents its sibling audio engine, which applies the same library/host boundary to
  sound. It is not a dependency of this repository, and this repository is not a dependency of it.

## Compatibility

Nothing to adopt. A host on 0.2.1 can move to 0.2.2 without changing code, configuration or peers,
and can equally stay on 0.2.1: the published behavior is identical. All six repository manifests use
0.2.2; both distributed packages are versioned together and the optional Capacitor adapter requires
core `^0.2.2`, a range its `^0.2.1` predecessor already admitted.

## Local validation

Clean `npm ci` on Node 22 / npm 10 succeeds without changing external dependency resolutions, and
the lockfile keeps every platform binary — a lockfile regenerated against a platform-filtered
`node_modules` records only the host's own, installs locally and fails on a Linux runner. Core
149/149 and sample 9/9 tests pass, as do the typechecks and the documentation and sensitive-data
gates. Local candidate checksums are not official release checksums: publication rebuilds from the
release commit and records its own assets and SHA-256 file.
